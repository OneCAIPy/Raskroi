# Проверочные случаи

## 1. Кромка не меняется при повороте

Деталь:

```text
Размер: 800×400
Количество: 2
Кромка по L1: 2 мм
Кромка по L2: 2 мм
Кромка по W1: нет
Кромка по W2: 0.4 мм
```

Ожидание:

- общий метраж кромки одинаковый независимо от поворота;
- на визуализации стороны кромки должны повернуться вместе с деталью.

## 2. Пропил не прибавляется к каждой детали

Настройки:

```text
Пила: 4 мм
Лист: 1000×1000
Детали: 2 штуки 400×400
```

Ожидание:

- между двумя соседними деталями учитывается один фактический пропил 4 мм;
- программа не делает каждую деталь условно 404×404 со всех сторон.

## 3. Остаток используется первым

Листы:

```text
Остаток: 1000×2800, приоритет 1
Стандарт: 1500×2800, приоритет 2
```

Ожидание:

- программа сначала пытается разместить детали на остатке;
- стандартный лист используется только после невозможности или исчерпания остатка.

## 4. Деталь не помещается без поворота

Лист:

```text
1000×2800
```

Деталь:

```text
1200×500
Поворот запрещён
```

Ожидание:

- программа не размещает деталь;
- выдаёт ошибку: деталь не помещается без поворота.

## 5. Деталь помещается с поворотом

Лист:

```text
1000×2800
```

Деталь:

```text
1200×500
Поворот разрешён
```

Ожидание:

- программа пробует поворот;
- размещает как 500×1200;
- кромка остаётся привязанной к логическим сторонам детали.

## 6. Отступы от краёв листа

Лист:

```text
1000×1000
```

Отступы:

```text
слева 10
справа 10
сверху 10
снизу 10
```

Ожидание:

- рабочая область становится 980×980;
- детали не выходят за эту область.

## 7. Размер после кромки

Деталь:

```text
Чистовой размер: 397×397
Кромка: 1 мм с двух сторон
Прифуговка: 0.5 мм с двух сторон
```

Ожидание:

```text
Размер без кромки:
397 - 1 - 1 = 395

Размер заготовки / распиловочный размер:
395 + 0.5 + 0.5 = 396
```

## 8. Неразмещённые детали

Если часть деталей не помещается, программа должна:

- не молчать;
- не терять детали;
- вывести список неразмещённых деталей;
- добавить предупреждение в Excel.

## 9. Терминальная подрезка меньше ширины пилы

Исходные данные:

```text
Полоса: 100×100 мм
Деталь: 98×100 мм
Пила: 4 мм
Начальная граница уже сформирована
```

Ожидание:

- деталь размещается;
- выполняется один конечный проход длиной 100 мм;
- номинальная площадь реза равна `100 × 4 = 400 мм²`;
- фактически удалённая площадь равна `100 × 2 = 200 мм²`;
- фиктивный остаток за деталью не создаётся.

## 10. Полный пропил между полезными элементами

Ожидание:

- между двумя соседними полезными элементами требуется вся ширина пилы;
- правило терминальной подрезки нельзя применять к внутреннему промежутку;
- при нехватке полного пропила размещение отклоняется.

## 11. Сформированная начальная граница не режется повторно

Для вложенной полосы, у которой первый дочерний элемент начинается от координаты
начала родительской полосы:

- начальная торцовка не добавляется;
- считаются только реально необходимые разделительные и конечные проходы.

Для полосы с положительным участком перед первым элементом:

- добавляется один начальный торцовочный проход;
- длина прохода равна полному поперечному размеру полосы.

## 12. Геометрическая и номинальная площадь резов

Ожидание:

- валидатор баланса использует `actual_removed_area`;
- отчёт, сопоставимый с БАЗИСом, использует `nominal_cut_area`;
- обе метрики строятся из одного производственного плана;
- экспортёры не рассчитывают их самостоятельно.

## 13. Производственный план строится из дерева

Ожидание:

- последовательные резы одного направления объединяются в один цикл;
- конечный отход не становится полезным выходом цикла;
- исходной областью первого цикла является полный физический лист;
- начальные и конечные торцовки из отступов входят в производственный план;
- вложенный цикл ссылается на породивший его выход родительского цикла;
- геометрическое дерево, координаты деталей и алгоритм размещения при этом не
  изменяются.

## 15. Физический поворот полосы

Ожидание:

- корневой цикл листа не создаёт событие поворота;
- каждый вложенный цикл создаёт ровно одно событие поворота на 90°;
- событие ссылается на выход родительского цикла и на вложенный цикл;
- направления связанных циклов перпендикулярны;
- поворот готовой детали `Rotation.DEG_90` не считается поворотом полосы.

Для 13 карт эталонного заказа БАЗИС распределение поворотов:

```text
3, 4, 5, 6, 4, 3, 6, 2, 4, 5, 4, 7, 6
```

Ожидаемый итог:

```text
72 цикла
- 13 корневых циклов исходных листов
= 59 физических поворотов полос
```

## 16. Установки размеров

Ожидание:

- установка создаётся только для выхода, за которым есть физический проход;
- два последовательных выхода одинакового размера используют одну настройку;
- изменение размера создаёт новое событие;
- начальная торцовка сбрасывает ранее сохранённый размер;
- следующий цикл без начальной торцовки может сохранить прежний размер;
- выход на уже готовой конечной границе без прохода не создаёт установку.

Для 13 карт эталонного заказа БАЗИС распределение установок:

```text
6, 9, 11, 12, 8, 8, 13, 5, 8, 11, 6, 14, 12
```

Ожидаемый итог:

```text
123 установки размеров
```

## 17. КИМ и заполнение рабочей области

Для эталонных итоговых данных БАЗИС:

```text
площадь распиловочных заготовок = 39,201903 м²
полная площадь 13 листов        = 44,408 м²
рабочая площадь после торцовок  = 43,212 м²
```

Ожидание:

- `material_utilization_percent = 88,28%`;
- `working_area_efficiency_percent = 90,72%`;
- метрики имеют разные имена и разные знаменатели;
- двусмысленное поле `efficiency_percent` отсутствует;
- общий КИМ учитывает только листы и входные обрезки, на которых размещены
  детали;
- неиспользованные доступные листы не входят в знаменатель;
- при отсутствии использованной площади результат равен нулю;
- веб-интерфейс показывает обе метрики отдельными строками.

Эта проверка подтверждает формулы на эталонных итогах. Совпадение текущей
раскладки с 13 картами БАЗИСа проверяется отдельно после многопроходной
оптимизации.

## 18. Расход кромки, материалы, отрезы и свес

Для каждой размещённой физической детали:

- `L1/L2` используют чистовой размер `L`;
- `W1/W2` используют чистовой размер `W`;
- одна оклеиваемая логическая сторона создаёт один `EdgeSegment`;
- общий свес отреза прибавляется к его базовой длине один раз;
- поворот детали не меняет длину или материал логической стороны;
- неразмещённые детали не входят в производственный расход результата;
- итоги группируются по названию материала и толщине.

Малый различимый пример:

```text
деталь 300×800
L1: ABS белая 1 мм, свес 10 мм
L2: ABS белая 1 мм, свес 0 мм
W1: ABS графит 2 мм, свес 20 мм
W2: ABS белая 1 мм, свес 5 мм
```

Ожидание:

```text
4 отреза
базовая длина = 300 + 300 + 800 + 800 = 2200 мм
свес = 10 + 0 + 20 + 5 = 35 мм
итоговая длина = 2235 мм
```

Эталон БАЗИС «Для Саши 23,07»:

```text
53 исходные позиции
93 физические детали
372 отреза
261526 мм = 261,526 м кромки
```

Эталон имеет нулевой свес и один материал `3019 АГТ Кромка Abs 22*1` толщиной
1 мм. Группировка нескольких сторон в один физический отрез им не проверяется.

## 19. Первое направление без геометрического реза

Исходные данные:

```text
физический лист: 100×100 мм
отступы: слева/справа 10 мм, сверху/снизу 20 мм
рабочая область и единственная деталь: 80×60 мм
```

Ожидание при `initial_cut_direction = horizontal`:

- геометрических разделительных резов нет;
- первый цикл торцовок горизонтальный;
- второй цикл торцовок вертикальный;
- выполнено четыре физических прохода;
- создан один поворот полосы между циклами.

Дополнительные проверки:

- значение по умолчанию — `vertical`;
- направление существующего геометрического реза настройкой не заменяется;
- неизвестное значение ручной формы возвращает явную ошибку ввода;
- при полном совпадении детали с физическим листом без отступов фиктивные циклы
  не создаются.

## 20. Детерминированный выбор из нескольких вариантов

Ожидание:

- строятся 24 уникальные комбинации эвристик;
- технические номера вариантов стабильны от 0 до 23;
- прежний однопроходный вариант имеет номер 0;
- два запуска с одинаковыми данными дают полностью одинаковый результат;
- вариант с неразмещённой деталью не может победить полный раскрой за счёт
  меньшего числа листов или проходов;
- число листов и КИМ сравниваются раньше производственных операций;
- затем по порядку сравниваются длина проходов, число проходов, повороты полос
  и установки размеров;
- полное равенство разрешается техническим номером варианта.

На фикстуре БАЗИС «Для Саши 23,07» первый набор вариантов даёт:

```text
размещено деталей: 93 из 93
использовано листов: 14
КИМ: 81,97%
длина проходов: 224,7712 м
физических проходов: 201
поворотов полос: 71
установок размеров: 131
```

Для сравнения прежний единственный проход использовал те же 14 листов, но имел
`242,4286 м`, 250 проходов, 124 поворота и 185 установок. Улучшение
производственных показателей подтверждает работу выбора вариантов, но не
считается достижением эталонной раскладки БАЗИСа на 13 листах.

## 23. Кромка и производственные показатели в ручной форме

Проверяются два совместимых формата:

- строка из пяти полей создаёт деталь без кромки;
- строка из девяти полей разбирает `L1/L2/W1/W2` независимо;
- ячейка стороны передаёт толщину, прифуговку, общий свес и материал;
- пустая ячейка или `-` означает отсутствие кромки;
- отрицательный параметр, лишнее поле ячейки или неположительный размер после
  кромки возвращает явную ошибку строки.

Сквозная проверка веб-формы подтверждает, что кромка доходит до SVG и готового
`EdgeConsumption`, а страница показывает длину и количество проходов, повороты
полос и установки размеров из внутреннего результата.

Эталон АГТ 3019 проходит через расширенный ручной ввод всех 53 позиций.
Ожидается:

```text
использовано листов: 13
длина кромки: 261,526 м
отрезов кромки: 372
профиль остатка: максимальная полезная площадь
возвратных остатков: 17

длина проходов: 216,9212 м

```

## 24. Возвратные остатки и КИМ с их учётом

Классификатор обходит дерево резов и принимает только листья с
`is_waste=True`. Внутренний узел, лист детали и свободный прямоугольник без
признака отхода возвратными не считаются.

Проверяются три включительные границы:

```text
минимальная длинная сторона: 400 мм
минимальная короткая сторона: 80 мм
минимальная площадь: 40 000 мм²
```

Эталонный список БАЗИСа содержит 17 прямоугольников:

```text
494,6×99; 538,6×196; 596×184,2; 138,2×1220;
529×122,8; 515×483,2; 1382,2×164; 914×83,2;
596×219,2; 596×219,2; 596×237,2; 1600×92,2;
971×106,2; 205,2×1220; 596×217,2; 596×218,2;
280,8×1220 мм.
```

Ожидание для дерева БАЗИСа:

```text
возвратных остатков: 17
общая площадь: 2,5551692 м² → 2,555 м² в отчёте
КИМ с учётом остатков: 94,03%
```

Текущий оптимизатор с профилем максимальной полезной площади строит другое
дерево. При тех же порогах его проверяемый результат АГТ 3019 имеет:

```text
возвратных остатков: 17
общая площадь: 2,08341456 м²
КИМ с учётом остатков: 92,9681...% → 92,97%
```

Различие с 17 остатками БАЗИСа не исправляется подменой классификации: оно
остаётся целевой метрикой следующих этапов оптимизации.

- 93 уникальных физических номера из 93;
- 13 листов и отсутствие неразмещённых деталей;
- неизменные 261,526 м и 372 отреза кромки;
- отсутствие ошибок геометрии, баланса площади и дерева резов.

Профиль максимальной площади объединяет окна `1…5`, `6…10` и `12…13`.
Длинный профиль объединяет `1…3`, `4…7` и `8…13`. Компактный профиль
объединяет `1…5`, `6…10` и `11…13`.

## 27. Отдельный поиск с лимитом листов

Малые случаи проверяют три разных статуса:

- площадь деталей больше доступной — `proven_impossible_by_area`;
- полная допустимая раскладка найдена — `found` и валидный `CuttingResult`;
- площадь достаточна, но ограниченный поиск решения не нашёл —
  `not_found_within_budget`, без ложного признака доказанной невозможности.

Отдельный быстрый тест АГТ 3019 запускает минимальный явный budget и проверяет,
что результат детерминированно остаётся ограниченным, использует не более
12 листов и не объявляет отрицательный исход доказательством.

Контрольный максимальный прогон выполняется отдельно от общего `pytest`:

```text
лимит листов: 12
вариантов: 24
beam width: 64
branch factor: 6
проверено состояний: 193340
отсечено состояний: 157900
статус: not_found_within_budget
глубина полного префикса beam-поиска: 47 деталей
лучший частичный результат: 84 из 93 деталей
```

Полная 12-листовая раскладка этим бюджетом не найдена. Тест не трактует это
как математическое доказательство невозможности.
