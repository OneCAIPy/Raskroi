## 3. Размеры детали и кромка

`.xbir` хранит четыре стадии размеров:

1. чистовой размер;
2. размер без кромки;
3. размер заготовки;
4. распиловочный размер.

Для этого заказа размер заготовки совпадает с распиловочным размером.

Формулы:

```text
L без кромки =
	L чистовая
	- толщина кромки W1
	- толщина кромки W2

W без кромки =
	W чистовая
	- толщина кромки L1
	- толщина кромки L2

L заготовки =
	L без кромки
	+ прифуговка W1
	+ прифуговка W2

W заготовки =
	W без кромки
	+ прифуговка L1
	+ прифуговка L2
```

Пример, позиция 34:

| Стадия | Размер |
|---|---:|
| Чистовой | 362×289 мм |
| Без кромки | 360×287 мм |
| Заготовка | 361×288 мм |
| Распиловочный | 361×288 мм |

У всех 93 деталей:

- кромка 1 мм на `L1`, `L2`, `W1`, `W2`;
- прифуговка 0,5 мм на каждой стороне;
- свес кромки отсутствует.

Подтверждённые итоги:

| Показатель | Значение |
|---|---:|
| Периметр распиловочных заготовок | 261,154 м |
| Длина облицовки | 261,526 м |
| Длина облицовки с учётом свесов | 261,526 м |
| Количество отрезов облицовки | 372 |

`372 = 93 × 4`: каждая физическая оклеиваемая сторона считается отдельным
отрезом.

Длина облицовки совпадает с суммой чистовых длин всех оклеиваемых сторон.
Разница с распиловочным периметром:

```text
261,526 - 261,154 = 0,372 м = 372 × 1 мм
```

Регрессионный тест строится из 53 исходных позиций и их количеств, разворачивает
их в 93 физические детали и формирует четыре `EdgeSegment` на деталь. Получено
без округления:

```text
372 отреза
261526 мм базовой длины
0 мм свеса
261526 мм итоговой длины
```

Для общего случая расход одного отреза хранится как:

```text
итоговая длина = чистовая длина логической стороны + общий свес отреза
```

Свес добавляется один раз на физический отрез. В этом заказе он равен нулю,
поэтому ненулевой свес дополнительно проверяется малым синтетическим тестом.

Этот заказ не проверяет:

- группировку нескольких сторон в один отрез ленты;
- формулу добавления свесов;
- правильность отображения разных материалов кромки после поворота, потому что
  все четыре стороны имеют одинаковую кромку.

## 4. Что хранит `.CUT`

`.CUT` — не G-code и не линейный список команд станку. Файл хранит:

- 13 раскладок;
- вложенное дерево полос и деталей;
- размеры и координаты узлов;
- ширину пропила;
- ссылки на 93 бирки.

Один внутренний узел дерева с дочерними элементами задаёт цикл параллельного
пиления текущего листа или полосы. Вложенный цикл означает дальнейшую обработку
полученной полосы после её поворота.

Корневой цикл каждой карты обрабатывает исходный лист и не считается
поворотом. Каждый вложенный цикл связан с конкретным выходом родительского
цикла и требует одного физического поворота полосы на 90°.

Распределение вложенных циклов и поворотов по 13 картам:

```text
3, 4, 5, 6, 4, 3, 6, 2, 4, 5, 4, 7, 6
```

Проверка итога:

```text
72 цикла пиления
- 13 корневых циклов исходных листов
= 59 физических поворотов полос
```

Поворот готовой детали на карте является другим признаком и в эти 59 событий
не входит.

## 5. Восстановленное правило физических проходов

Для одного цикла нужно различать:

- начальную торцовку;
- разделительные резы между соседними полезными элементами;
- конечную торцовку;
- уже существующие чистые границы родительской полосы.

Подтверждённое правило:

1. Начальная торцовка выполняется только тогда, когда первый дочерний элемент
   начинается не от уже сформированной границы родительской полосы.
2. Между соседними полезными элементами выполняется один проход с полным
   пропилом.
3. Конечная торцовка выполняется только тогда, когда последний элемент не
   заканчивается на уже сформированной границе родительской полосы.
4. Уже сформированная граница повторно не торцуется.
5. Длина прохода равна полному поперечному размеру обрабатываемого листа или
   полосы, а не длине границы отдельной детали.

В данном заказе у всех 72 циклов есть положительная конечная подрезка. Поэтому
для него действует сокращённая формула:

```text
проходов цикла =
	количество дочерних элементов
	+ 1, если нужна начальная торцовка
```

Суммарно:

```text
72 цикла пиления
= 13 циклов исходных листов
  + 59 вложенных циклов полос

196 проходов
= 152 прохода по задним границам дочерних элементов
  + 44 начальные торцовки
```

В 28 циклах начальная граница уже была сформирована предыдущим резом. Поэтому
безусловное добавление начальной торцовки каждому циклу ошибочно: оно дало бы
224 реза вместо 196.

### 5.1. Восстановленное правило установок размеров

Установка размера относится не к каждому проходу, а к размеру выхода цикла,
за которым выполняется физический проход. Для вертикального цикла это ширина
выхода, для горизонтального — его высота.

Подтверждённый алгоритм подсчёта:

```text
активный размер = отсутствует

для каждого прохода в производственном порядке:
	если это начальная торцовка:
		активный размер = отсутствует
	иначе, если проход связан с выходом:
		размер = размер выхода вдоль направления пиления
		если активного размера нет или он отличается:
			добавить установку размера
		активный размер = размер
```

Следствия:

- начальная торцовка сама не является установкой размера выхода;
- одинаковые подряд размеры используют одну настройку;
- начальная торцовка сбрасывает ранее сохранённую настройку;
- цикл без начальной торцовки может переиспользовать размер предыдущего цикла;
- если задняя граница последнего выхода уже готова и проход не выполняется,
  установка для этого выхода не нужна.

В `.CUT` содержится 152 выхода: 93 готовые детали и 59 промежуточных полос.
Внутри отдельных циклов они образуют 124 серии одинаковых размеров. На карте 4
два последовательных вложенных цикла начинаются без начальной торцовки и оба
используют размер 196 мм, поэтому вторая настройка сохраняется:

```text
124 серии внутри циклов
- 1 переиспользование размера между циклами
= 123 установки размеров
```

Распределение по картам совпадает с отчётом БАЗИСа без расхождений:

```text
6, 9, 11, 12, 8, 8, 13, 5, 8, 11, 6, 14, 12
```

## 6. Пропил и терминальная подрезка

В этом дереве:

- все 80 промежутков между соседними полезными элементами равны 4,4 мм;
- найдено 9 конечных подрезок меньше 4,4 мм;
- минимальная конечная подрезка равна 2 мм.

Следовательно:

- между двумя полезными частями нужен полный пропил;
- на конечной границе допустима положительная подрезка меньше ширины пилы;
- такой проход считается полноценным физическим проходом по всей длине полосы;
- создавать фиктивный положительный остаток за деталью не требуется.

Для метрик необходимо хранить две разные площади:

```text
nominal_cut_area =
	сумма(длина физического прохода × номинальная ширина пилы)

actual_removed_area =
	геометрически удалённая площадь внутри исходного материала
```

`nominal_cut_area` нужна для сопоставления со статистикой БАЗИСа.
`actual_removed_area` нужна для баланса площадей и валидатора.

При терминальной подрезке 2 мм и пиле 4,4 мм:

- в номинальную площадь входит `длина прохода × 4,4 мм`;
- в фактически удалённую площадь входит только `длина прохода × 2 мм`.

Номинальную площадь нельзя использовать для геометрического баланса листа.

## 7. КИМ

БАЗИС использует полную площадь фактически задействованного листового материала,
а не рабочую область после вычитания торцовок.

```text
КИМ =
	площадь распиловочных заготовок
	/ площадь использованных листов и входных обрезков
	× 100%
```

Для эталонного заказа:

```text
площадь заготовок = 39,201903 м²
площадь листов = 13 × 2,8 × 1,22 = 44,408 м²

КИМ = 39,201903 / 44,408 × 100% = 88,2767...%
```

В отчёте: `88,28%`.

При минимальных торцовках 15 и 10 мм по соответствующим направлениям рабочая
площадь тех же 13 листов равна:

```text
13 × (2,8 - 2 × 0,015) × (1,22 - 2 × 0,010) = 43,212 м²

заполнение рабочей области =
	39,201903 / 43,212 × 100% = 90,7199...% → 90,72%
```

Следовательно, для этого эталона КИМ и заполнение рабочей области различаются:

| Метрика модели | Значение |
|---|---:|
| `material_utilization_percent` | 88,28% |
| `working_area_efficiency_percent` | 90,72% |

```text
КИМ с учётом обрезков =
	(площадь заготовок + площадь возвратных обрезков)
	/ площадь использованного материала
	× 100%
```

В отчёте:

- площадь возвратных обрезков — 2,555 м²;
- КИМ с учётом обрезков — 94,03%.

Заполнение рабочей области после торцовок — полезная внутренняя метрика, но это
не КИМ БАЗИСа. В модели эти показатели должны иметь разные имена.

Числовая проверка `88,28%` подтверждает формулу метрики на итоговых данных
БАЗИСа. Она не означает, что текущий однопроходный оптимизатор уже повторяет
эталонную раскладку на 13 листах: для этого отдельно нужен этап многопроходной
оптимизации.

## 10. Что пока не доказано

По этому набору файлов нельзя достоверно восстановить:

- внутренний поисковый алгоритм БАЗИСа;
- настройки и порядок критериев конкретного запуска оптимизации;
- линейную последовательность команд конкретного станка;
- перенос установки размера между листами или при другом порядке выполнения
  циклов;
- правила свесов и объединения нескольких кромок в один отрез;
- визуальное соответствие разных `L1/L2/W1/W2` после поворота.

Правило установок подтверждено для производственного порядка циклов,
восстановленного из этого `.CUT`. Оно не раскрывает внутреннюю оптимизацию
порядка операций БАЗИСа или команды конкретного станка.

## 11. Требования к внутренней модели

Дерево геометрического раскроя и производственный план связаны, но это не одна
и та же сущность.

Внутренняя модель результата должна содержать готовые:

- геометрическое дерево резов;
- упорядоченные циклы пиления;
- физические проходы пилы;
- события поворота полос;
- события установки размеров;
- количество и длину проходов;
- номинальную и фактически удалённую площадь пропила;
- КИМ и заполнение рабочей области как разные метрики;
- расход кромки по материалам и количество отрезов.

SVG, Excel и будущий станочный экспорт должны только отображать эти данные, а
не пересчитывать их каждый по-своему.
